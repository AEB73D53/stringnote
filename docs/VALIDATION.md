### 变调夹试听更新（2026-10-23）

43 项单元测试、TypeScript 与生产构建通过。新增实际 PCM 频谱测试，覆盖 C 手型夹 0、2、4、9 品，以及旋律随品位升高和休止保留；同时检查变调夹数值边界、缓存签名与简单指法推荐的总位移。

`tests/capo_browser.py` 在本地 Chromium 实测通过：保持 C 手型，夹 0、2、4 品时，采样吉他的主要低音依次为 130.75、146.75、164.75 Hz。扫描整个 70–190 Hz 频段，确认夹 4 品不会错误改用低八度 E2 指位。改变品位会暂停过期伴奏，点击上方试听或底部合成伴奏播放后生成新版；回到 0 品恢复原 WAV。

移调与变调夹叠加、“更容易的指法”保持实际调性、原录音往返切换不改文件、ChordPro 导出后重新导入恢复实际调性、390px 手机无横向溢出均通过，未发现页面异常。简单指法与 ChordPro 重新导入可能选择不同声部排列，因此以实际音高和调性核对，不要求 WAV 字节完全相同。结果保存在忽略的 `test-results/capo-browser-results.json`。

同步将编辑输入框与 JSON 导出说明改为“基础和弦”，并在最终文案上顺序通过 `tests/browser_smoke.py` 和 `tests/preview_browser.py`；覆盖既有编辑、试听、撤销、原录音保存恢复及手机入口。

### 木吉他音色更新（2026-10-22）

`npm test` 的 36 项测试与生产构建通过，包括 684 种根音、和弦质量及斜杠低音组合的吉他排列检查。`tests/preview_browser.py` 再次通过，覆盖编辑与撤销后的实际 WAV、原录音来回切换及保存恢复、390px 手机试听入口。异步合成检查会等待新音频开始播放，避免把上一段暂停位置当成新版音频。

新增 `tests/guitar_browser.py` 实际加载同站的 385,710 字节采样文件，验证音频播放时间增长、修改后声音改变、恢复后声音相同、后续试听复用已解码音色。拦截音色文件返回 503 时，本机弦模型仍生成可播放且内容不同的伴奏；两条路径均无页面异常。

8 秒样本的输出均为 22050 Hz 单声道 PCM WAV，峰值 26868/32768，未发生数字削波；采样路径与回退路径的实际内容摘要不同。测试结果位于忽略的 `test-results/guitar-browser-results.json`。这些检查证明加载、音高排列、时序和播放行为；音色好听程度仍需实际听感判断，未宣称等同真人录制或已在真实手机上验收。
